## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# test coverage
$ npm run test:cov
```

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.

## HLS Video Streaming – Folder Structure

This section documents the folder structure prepared for future HLS (HTTP Live Streaming) video conversion support.

### `videos/input/`

> **Purpose:** Drop your original, unprocessed MP4 test video files here.

- This folder serves as the **source directory** for the HLS conversion pipeline.
- When FFmpeg processing is implemented, it will read files from this location.
- Example: `videos/input/sample.mp4`

### `videos/output/`

> **Purpose:** FFmpeg will write the generated HLS files into this directory.

- This folder will contain **HLS playlist files** (`.m3u8`) and **transport stream segments** (`.ts`) after conversion runs.
- Each video will typically get its own sub-folder, e.g. `videos/output/sample/index.m3u8`.
- The NestJS server will eventually serve these static files so that HLS-compatible players (e.g. HLS.js in the React frontend) can stream them.

> **Note:** Both folders contain a `.gitkeep` file so Git tracks them even when empty. Add `videos/input/*` and `videos/output/*` to `.gitignore` if you do not want test media committed to the repository.
